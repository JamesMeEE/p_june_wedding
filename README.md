# TARVIQO · ระบบลงเวลาทำงาน

ระบบลงเวลาเข้า–ออกงานสำหรับใช้บนมือถือเป็นหลัก ตรวจสอบทั้ง **เวลา / เครื่องที่ใช้ / ตำแหน่งที่อยู่**
พร้อมระบบตารางกะ กติกาเวลาแยกตามกลุ่ม คำนวณชั่วโมงงานและ OT ระบบใบลา คำขอแก้เวลาที่ต้องผ่านการอนุมัติ
ประวัติการแก้ไขย้อนหลัง และการปิดงวดส่งฝ่ายบัญชี

สร้างด้วย Next.js 15 (App Router) · TypeScript · Prisma · PostgreSQL · Tailwind CSS · flatpickr

---

## สิ่งที่ระบบทำได้

| ส่วน | รายละเอียด |
| --- | --- |
| เข้าสู่ระบบ | เลือกชื่อจาก dropdown + กรอกรหัสผ่าน · ถ้า **ไม่เลือกชื่อ** แล้วกรอกรหัสผู้ดูแล (ค่าเริ่มต้น `1150`) จะเข้าเป็นผู้ดูแลระบบทันที |
| ลงเวลา | ปุ่มเข้า–ออกงาน พร้อมตรวจ 3 ชั้น: เครื่องต้องได้รับอนุมัติ · ต้องอยู่ในรัศมีพื้นที่ทำงาน · ต้องไม่เช้าเกินเกณฑ์ |
| ตรวจเครื่อง | เครื่องใหม่จะถูกลงทะเบียนอัตโนมัติในสถานะ *รออนุมัติ* ผู้ดูแลกดอนุมัติ/ปฏิเสธได้รายเครื่อง |
| ตรวจตำแหน่ง | กำหนดได้หลายสถานที่ แต่ละแห่งมีพิกัดและรัศมีของตัวเอง · อยู่นอกพื้นที่ = ลงเวลาไม่ได้ |
| ประเภทการลงเวลา | สำนักงาน · ไซต์งาน · งานนอกสถานที่ · ทำงานที่บ้าน — สองแบบหลังไม่ตรวจรัศมี แต่ต้องมีใบอนุมัติล่วงหน้า |
| ตารางกะ | กำหนดรายคน รายวันในสัปดาห์ ว่าเข้างานกี่โมงถึงกี่โมง พักกี่นาที · รองรับกะข้ามคืน |
| กติกาเวลา | เกณฑ์สาย ผ่อนผันออกก่อน จุดเริ่มนับ OT และการปัด OT · ตั้งแยกตามพนักงานหรือทั้งตำแหน่งได้ |
| คำนวณเวลา | ชั่วโมงงาน · OT (เริ่มนับหลังเลิกงาน + นาทีที่กำหนด) · มาสาย · ออกก่อน · วันขาด · วันลา · วันหยุด (ทำงานวันหยุด = OT ทั้งหมด) |
| ใบลา | ยื่น 7 ประเภท เต็มวัน/ครึ่งเช้า/ครึ่งบ่าย · ระบบนับเฉพาะวันทำงานตามตารางกะ |
| คำขอแก้เวลา | ลืมลงเวลา → พนักงานยื่นคำขอ → หัวหน้าอนุมัติ → ระบบเขียนค่าใหม่ + เก็บค่าก่อน/หลัง |
| สายอนุมัติ | แต่ละคนมี "หัวหน้างาน" หนึ่งคน ใบลาและคำขอทุกชนิดวิ่งไปหาคนนั้น · ไม่ได้กำหนด = ผู้ดูแลระบบพิจารณา |
| รับรอง OT | หัวหน้ากดรับรองชั่วโมงงานและ OT รายเดือนของลูกทีม · ถ้ามีการแก้เวลาภายหลังระบบเตือนให้รับรองใหม่ |
| ภาพรวมรายวัน | หน้าเดียวเห็นทุกคน — ใครมาแล้ว ใครสาย ใครยังไม่ลงเวลา ใครลา · กรองตามตำแหน่ง/พื้นที่ |
| ประวัติการแก้ไข | Audit Log ทุกการแก้เวลา อนุมัติ ปิดงวด และเปลี่ยนกติกา พร้อมค่าก่อน–หลังและชื่อผู้ทำ |
| ปิดงวดเงินเดือน | ปิดงวดแล้วห้ามแก้เวลาของเดือนนั้นทุกช่องทาง · เปิดใหม่ได้แต่ถูกบันทึกไว้ |
| แจ้งเตือน | กระดิ่งในระบบ — คำขอรออนุมัติ ผลการพิจารณา มาสาย และลืมลงเวลาออก |
| รายงาน | สรุปรายเดือนทั้งองค์กร พร้อมรายการผิดปกติและสถานะการรับรอง · ดาวน์โหลด CSV · เจาะดูรายวันและแก้เวลาย้อนหลังได้ |

**หมายเหตุด้านการออกแบบ** — ทุกจุดที่กำลังโหลดข้อมูลจะแสดง *สปินเนอร์/สเกเลตัน* ส่วนทุกจุดที่กำลัง **บันทึก**
จะขึ้น *overlay ทับทั้งจอ* พร้อมเตือนไม่ให้ปิดหน้า และมี `beforeunload` กันปิดแท็บกลางคัน
วันที่ทั้งระบบเป็นปฏิทินไทย พ.ศ. เวลาเป็น 24 ชั่วโมง และไม่มี radio button — ใช้ toggle/segmented แทนทั้งหมด

## เริ่มใช้งานบนเครื่องตัวเอง

```bash
npm install
cp .env.example .env          # แล้วแก้ค่าใน .env
npx prisma migrate deploy     # สร้างตารางในฐานข้อมูล
npm run dev                   # http://localhost:3000
```

ต้องมี PostgreSQL อยู่ก่อน (ใช้ Postgres บน Railway ตรง ๆ ก็ได้ โดยก๊อป `DATABASE_URL` มาใส่)

ค่าใน `.env`

| ตัวแปร | ความหมาย |
| --- | --- |
| `DATABASE_URL` | connection string ของ PostgreSQL |
| `AUTH_SECRET` | คีย์สำหรับเซ็น session cookie — ต้องยาว ≥ 32 ตัว (`openssl rand -base64 48`) |
| `ADMIN_PASSCODE` | รหัสผู้ดูแลกลาง ค่าเริ่มต้น `1150` |
| `APP_TIMEZONE` | ค่าเริ่มต้น `Asia/Bangkok` — ระบบคิด "วันของกะ" ตามเขตเวลานี้เสมอ |

## Deploy ขึ้น Railway (เชื่อมกับ GitHub)

### 1. ดันโค้ดขึ้น GitHub

```bash
git add .
git commit -m "ระบบลงเวลาทำงาน TARVIQO"
git push origin main
```

### 2. สร้างโปรเจกต์บน Railway

1. เข้า [railway.app](https://railway.app) → **New Project** → **Deploy from GitHub repo**
2. เลือก repo นี้ Railway จะอ่าน `railway.json` แล้ว build ให้เอง
3. ในโปรเจกต์เดียวกัน กด **New** → **Database** → **Add PostgreSQL**

### 3. ตั้งค่า Variables ของ service ที่เป็นเว็บ

| Key | Value |
| --- | --- |
| `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` ← พิมพ์แบบนี้เพื่ออ้างถึง Postgres ในโปรเจกต์ |
| `AUTH_SECRET` | สตริงสุ่มยาว ๆ ของคุณเอง |
| `ADMIN_PASSCODE` | รหัสผู้ดูแล เช่น `1150` (แนะนำให้เปลี่ยนหลังติดตั้งเสร็จ) |
| `APP_TIMEZONE` | `Asia/Bangkok` |

### 4. เปิด public domain

**Settings → Networking → Generate Domain**

ตอน deploy ระบบจะรัน `scripts/start.mjs` ซึ่งจะ `prisma migrate deploy` ให้อัตโนมัติ
แล้วค่อยเปิดเซิร์ฟเวอร์ จึงสร้างตารางทั้งหมดในครั้งแรกเอง ไม่ต้องรันคำสั่งเพิ่ม

> **สำคัญ:** ต้องเปิดผ่าน **HTTPS** เท่านั้น เพราะเบราว์เซอร์จะไม่ยอมให้ขอพิกัด GPS บน HTTP
> โดเมนของ Railway เป็น HTTPS อยู่แล้ว

## แก้ปัญหาตอน deploy

### Healthcheck failure

`/api/health` ถูกออกแบบให้ตอบ 200 เสมอโดยไม่แตะฐานข้อมูล และ `scripts/start.mjs`
จะเปิดเซิร์ฟเวอร์ต่อแม้ migration จะล้ม ดังนั้นถ้ายังเจอ healthcheck failure อยู่
ให้ไล่ตามนี้

1. **เปิด deploy log** — Railway → service ของเว็บ → **Deployments** → คลิก deployment ล่าสุด → **View Logs**
   สคริปต์จะพิมพ์กรอบข้อความบอกสาเหตุไว้ให้แล้ว (`MISSING ENVIRONMENT VARIABLES` หรือ `DATABASE MIGRATION FAILED`)

2. **ตรวจว่า build สำเร็จจริง** — ถ้า log หยุดตั้งแต่ช่วง build แปลว่าปัญหาอยู่ที่ build ไม่ใช่ healthcheck

3. **ตรวจ Variables** — ต้องมีครบทั้ง `DATABASE_URL`, `AUTH_SECRET`, `ADMIN_PASSCODE`
   จุดที่พลาดบ่อยที่สุดคือ `DATABASE_URL` เขียนเป็น `${{Postgres.DATABASE_URL}}`
   แต่ service ฐานข้อมูลไม่ได้ชื่อ `Postgres` — ชื่อใน `${{...}}` ต้องตรงกับชื่อ service เป๊ะ ๆ
   วิธีที่ชัวร์กว่าคือกด **Variable Reference** แล้วเลือกจากรายการแทนการพิมพ์เอง

4. **ตรวจว่า Postgres อยู่ในโปรเจกต์เดียวกับเว็บ** — คนละโปรเจกต์จะอ้างอิงตัวแปรข้ามกันไม่ได้

### ตรวจสถานะจริงจากเบราว์เซอร์

เมื่อเว็บขึ้นแล้ว เปิด

```
https://<โดเมนของคุณ>/api/health?deep=1
```

จะได้ JSON บอกว่า env ตัวไหนตั้งค่าแล้ว ต่อฐานข้อมูลได้หรือไม่ พร้อมข้อความบอกวิธีแก้เป็นภาษาไทย
เช่น

```json
{
  "env": { "DATABASE_URL": "postgresql://...:5432/railway", "AUTH_SECRET": "ตั้งค่าแล้ว" },
  "database": { "connected": true, "latencyMs": 12, "employees": 0 }
}
```

ถ้า `connected` เป็น `false` ให้อ่านช่อง `hint` แล้วแก้ตามนั้น

### ถ้าจำเป็นต้องปิด healthcheck ชั่วคราว

Railway → service → **Settings → Deploy → Healthcheck Path** แล้วลบค่าทิ้ง
เว็บจะขึ้นทันทีโดยไม่รอ healthcheck ทำให้เข้าไปดู log และ `/api/health?deep=1` ได้ง่ายขึ้น

## ลำดับการตั้งค่าครั้งแรก

1. เปิดเว็บ → **ไม่เลือกชื่อ** ใน dropdown → กรอกรหัส `1150` → เข้าสู่ระบบ
2. **พื้นที่ทำงาน** — เพิ่มอย่างน้อยหนึ่งแห่ง (มีปุ่ม "ใช้ตำแหน่งปัจจุบัน" ให้กดตอนอยู่หน้างาน)
3. **พนักงานและตำแหน่ง** — สร้างตำแหน่งก่อน แล้วเพิ่มพนักงาน ตั้งรหัสผ่าน เลือกหัวหน้างาน
4. **ตารางเวลาทำงาน** — ตั้งกะรายคน (ค่าเริ่มต้นให้ไว้แล้ว จ.–ศ. 09:00–18:00 พัก 60 นาที)
5. **กติกาเวลา** — ตั้งเกณฑ์สายและ OT (เช่น สาย 5 นาที · OT เริ่มหลังเลิกงาน 30 นาที · OT ขั้นต่ำ 30 นาที)
   แล้วผูกกับตำแหน่งหรือรายบุคคล ถ้าไม่ตั้ง ระบบใช้ค่ากลางในหน้าตั้งค่าระบบ
6. **วันหยุดบริษัท** — ใส่วันหยุดประจำปี
7. ให้พนักงานเข้าสู่ระบบด้วยมือถือตัวเองครั้งแรก → เครื่องจะโผล่ที่ **เครื่องลงเวลา** → กดอนุมัติ
8. เปลี่ยน `ADMIN_PASSCODE` บน Railway แล้ว redeploy หนึ่งครั้ง

**รอบเดือน (ทุกสิ้นเดือน)**

1. หัวหน้าเคลียร์คำขอที่ค้างในหน้า **ศูนย์อนุมัติ** (ใบลา · แก้เวลา · นอกสถานที่)
2. หัวหน้ากด **รับรอง OT** ของลูกทีมทุกคน
3. ผู้ดูแลเปิด **รายงานและปิดงวด** → ตรวจแถบเตือนรายการค้าง → ดาวน์โหลด CSV ส่งบัญชี → กด **ปิดงวด**

## โครงสร้างโค้ด

```
prisma/
  schema.prisma            โครงฐานข้อมูลทั้งหมด
  migrations/              migration ที่ Railway ใช้ตอน deploy
src/
  app/
    login/                 หน้าเข้าสู่ระบบ
    (app)/                 ทุกหน้าที่ต้องล็อกอิน (มี AppShell ครอบ)
      dashboard/           หน้าลงเวลา + หน้าแรกของผู้ดูแล
      attendance/          ประวัติการลงเวลาของตัวเอง
      leave/               ยื่นใบลา + ขอทำงานนอกสถานที่
      approvals/           ศูนย์อนุมัติ: ใบลา · แก้เวลา · นอกสถานที่ · รับรอง OT
      team/                ผังสายบังคับบัญชา
      admin/               ภาพรวมรายวัน พนักงาน ตาราง เครื่อง สถานที่ วันหยุด
                           กติกาเวลา รายงาน+ปิดงวด ประวัติการแก้ไข ตั้งค่า
    api/                   route handlers ทั้งหมด
  components/
    ui/Overlay.tsx         overlay ตอนบันทึก (ล็อกจอ + กันปิดแท็บ)
    ui/Spinner.tsx         สปินเนอร์และสเกเลตัน
    ui/Pickers.tsx         flatpickr ไทย/พ.ศ. และช่องเวลา 24 ชม.
    ui/Choice.tsx          segmented + option cards (ใช้แทน radio)
    ui/Toggle.tsx          สวิตช์เปิด/ปิด
    AppShell.tsx           แถบข้าง (จอใหญ่) / แถบล่าง + ลิ้นชัก (มือถือ)
  lib/
    time.ts                ตัวช่วยเวลาไทยทั้งหมด (วันของกะ, พ.ศ., HH:mm)
    attendance.ts          สูตรคำนวณชั่วโมงงาน/OT/สาย + ป้ายชื่อภาษาไทย
    policy.ts              ไล่หากติกาเวลาที่มีผลจริง (คน → ตำแหน่ง → ค่าเริ่มต้น → ค่ากลาง)
    timeedit.ts            เขียนเวลาใหม่ + คำนวณซ้ำ (ใช้ทั้งทางผู้ดูแลและการอนุมัติคำขอ)
    payroll.ts             ตรวจว่างวดนั้นถูกปิดหรือยัง (กันการแก้เวลาย้อนหลัง)
    audit.ts               เขียนประวัติการแก้ไขพร้อมค่าก่อน/หลัง
    notify.ts              สร้างการแจ้งเตือนในระบบ (มี dedupeKey กันซ้ำ)
    daily.ts               ประกอบภาพรวมรายวันของทั้งองค์กร
    geo.ts                 haversine + geofence
    report.ts              ประกอบรายงานรายวัน/รายเดือน
```

**หมายเหตุเรื่องการแจ้งเตือน** — ระบบไม่มีตัวตั้งเวลา (cron) เรื่องที่ต้องตรวจเอง เช่น *ลืมลงเวลาออก*
จึงถูกตรวจตอนที่ผู้ใช้เปิดหน้าเว็บแล้วสร้างการแจ้งเตือนให้ (มี `dedupeKey` กันสร้างซ้ำ)
ถ้าวันหลังต้องการให้เตือนแม้ไม่มีใครเปิดเว็บ ต้องเพิ่ม cron job ที่ยิงเข้ามาเป็นระยะ
